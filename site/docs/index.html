Install and updates

Solara runs on macOS 26 or later, on Apple Silicon. Each release is signed with a Developer ID and notarized by Apple.

  1. Download the DMG from the latest release.
  2. Open it and drag Solara to Applications.

Or install it with Homebrew:

brew install --cask andrewbenson/solara/solara

Updates

Solara installs its own updates from GitHub Releases, using Sparkle. Pick a channel in Settings › General › Update channel.

Stable
Receives stable releases only.
Nightly
Receives newer prereleases as well as stable releases.

Switching from Nightly back to Stable waits for the next stable build. It never downgrades.

If you used 0.0.1, install 0.1.0 or later from the DMG over it. 0.1.0 has a new app identity and starts with a fresh profile.

Sync

Sync keeps your profiles, bookmarks, history, tabs, passwords, extensions and settings the same across your Macs. It has no server and no account. Each Mac reads and writes sealed files in a folder you choose, and whatever syncs that folder carries them between Macs.

  • The folder. By default it's Solara Sync in iCloud Drive. Dropbox, a NAS or a USB drive work the same way.
  • End-to-end encrypted. Every file is sealed with a key only your Macs hold. Anyone who can open the folder sees files they can't read.
  • The recovery phrase. Turning sync on makes a 24-word phrase and offers a Recovery Kit to save as a PDF. Keep it somewhere other than this Mac: it's the only way back in if you lose your Macs.
  • Each profile chooses. Turn sync on per profile in Settings › Sync › Profiles. A synced profile your other Mac doesn't have yet is offered there as Add to This Mac.

Adding another Mac

  1. On the new Mac, open Solara and choose Use Solara from your other Mac.
  2. On the Mac that already syncs, open Settings › Sync and choose Connect another Mac or Review request.
  3. Check that both Macs show the same six characters, then choose Allow and confirm with Touch ID or your password.

You can enter the recovery phrase on the new Mac instead. Pairing shows this Mac's name to the Mac you're pairing with before you compare codes, even if you cancel.

The solara command

The solara command drives a running Solara from the terminal. Turn it on in Settings with Let the solara command control Solara, under Command line. Solara installs the command into ~/.local/bin and keeps it up to date with the app. While it's connected, a pill at the bottom of the page says so, with a Stop button.

solara tabs
solara sidebar
solara exec 'await tab.go_to("https://example.com")'
solara exec -f report.py
solara tabs
Lists every open tab in every window, sorted by memory, without waking sleeping tabs.
solara exec
Runs Python against the browser, with the current tab, your open tabs and your history at hand.
solara sidebar, group, folder, tab
List and arrange the sidebar: make groups and folders, and move, pin, rename and reorder tabs. Add --dry-run to see a change first.
solara scripts
Writes, tests and installs userscripts. Violentmonkey and Tampermonkey scripts work as they are.
solara skills install
Installs a skill that teaches coding agents how to use the command.

Setting Solara up from files

Solara can read its settings, keyboard shortcuts and profile themes from JSON files, so you can keep them in your dotfiles and get the same browser on every Mac. It reads them at launch and again whenever you save. It never writes to them.

mkdir -p ~/.config/solara/themes

~/.config/solara/config.json:

{
  "settings": {
    "appearance": "dark",
    "sidebarWidth": 240,
    "bookmarksBar": "newTab"
  },
  "keybindings": {
    "toggleSidebar": "⌘S",
    "print": ""
  },
  "theme": "ocean",
  "profiles": {
    "Work": { "theme": "forest" }
  }
}

Every part is optional. Anything set in the file wins over Settings, which shows it greyed out. Take it out of the file and your choice in Settings comes back. Values from the file never sync.

Themes

A theme sets a profile's gradient. Save it as ~/.config/solara/themes/ocean.json and name it in config.json:

{
  "colors": ["#3366FF", "#00CCAA"],
  "angle": 135,
  "intensity": 0.6,
  "grain": 0.2,
  "dark": { "colors": ["#1A2A66", "#006655"], "intensity": 0.8 }
}

Hooks

Hooks are rules in ~/.config/solara/hooks.json. They can block pages or rewrite where they go, strip tracking parameters, send links from an app to a profile, file downloads into a folder, deny the camera or microphone to some sites, and play a sound, show a notification or run a program when something happens.

{
  "hooks": [
    { "name": "no-tracking", "match": { "hosts": ["*.example.com"] }, "stripParams": ["utm_*", "fbclid"] },
    { "name": "old-reddit", "match": { "hosts": ["www.reddit.com"] }, "rewrite": "https://old.reddit.com{path}{query}{fragment}" },
    { "name": "slack-to-work", "match": { "apps": ["com.tinyspeck.slackmacgap"] }, "openIn": { "profile": "Work" } },
    { "name": "chime", "on": ["download.finished"], "sound": "Glass" }
  ]
}

Hooks are tried in order and the first that applies decides. Settings › Advanced › Hooks lists every rule and shows any error in the file. The file must belong to you and not be writable by other users.

Privacy

  • No account. Nothing to sign up for. Sync, if you turn it on, goes through your own folder.
  • No telemetry. No usage data and no crash reports leave your Mac.
  • No Google background services. They're compiled out of the engine.
  • uBlock Origin is built in.
  • No AI features.

This site has no analytics either. The download button asks GitHub for the latest release, and that's all.
