# 0.4.4 → 0.4.5 release gate

0.4.5 (build 107, release `3f516d0f`, built at `be459821`) and 0.4.4 (build 106, release `0f510e08`) use
Chromium 157.0.8103.50 and native API 66. The candidate is the signed, notarized
`dist/0.4.5/export/Solara.app` (codesign and spctl: "accepted, Notarized Developer ID"); `dist/0.4.4/export`
links to the retained control at `/Users/andrewbenson/.cache/solara-lead/controls/0.4.4/export`.
Native-bench and the J2 journey used the candidate's API-66 bench bundle on both sides; js-bench and tab-actions
used each app's own shipped `main.jsbundle`. All used `SOLARA_NATIVE_BOOKMARKS=1`, ad hoc copies on both sides
(`BENCH_SIGN_IDENTITY=-`), offline, on 2026-11-20 on the Hill Studio under the perflab lock, interleaved, with
`caffeinate -d`. Native-bench: launch x6, session x5 and standalone windows x5 per app. JS: five alternating runs
per app. tab-actions: 4 launches per app, 5 of each action per launch. J2: 4 runs per app, 10 iterations each.

**SHIP.** Smoke, the update test and every host harness pass. No timing row is more than 15% worse with
separated ranges, and the two rows that held 0.4.4 are level at n=5. The ratchet's 14 counts over are
`c0f2a592`'s, raised in `896ed433`, and cost no measured time. J2 is not comparable this gate (below).

Each page now writes `historyKnown` to the pages store once, when it reports a committed URL, so Back knows
whether it has somewhere to go: one more pages update per opened tab and one at launch, intended. `useBackAction`
and the swipe overlay subscribe to the raw value, so the flip re-renders `SolaraSwipe` and `SwipeArea` even for a
tab with no opener, and their new selectors add the typing +6: waste, fixed for 0.4.6 by reading `historyKnown`
only when the tab has an opener. The noisy open counts follow. js-bench's open20 counts rise the same way
(commits 381 → 421, hostUpdates 948 → 1063, renders 2880 → 3085, ranges separate) while open20 task time does not
(below).

Values below are medians; parentheses give min–max and n. Native session rows use per-run values, new-window
rows pool five session and five standalone-window run medians (n=10), tab-actions ranges are per-launch medians.
Evidence is under `~/Developer/workbench/solara/gate45/` on the Hill Studio: `perf-gate/{native,js,tabs,j2,j2b}/`,
`logs/`, `analyze.py`, `metric-analysis.json`.

Every native run began and ended awake and unlocked, with no samples left out; all idle windows recorded zero
input and zero pointer seconds. All ten native sessions reported 537,560 URLHaus entries. The host was not
quiet when the gate began (load 16: another agent's `swift test` and a stray five-hour `grep`); both ended before
the timing steps, which started at load 3.2. During the timing steps the 1-minute load stayed between 1.2 and
5.0, except at about 08:31–08:37 (js runs 0.4.4-4 and 0.4.5-4), when it reached 7.9; OS work (Spotlight,
mediaanalysisd) ran throughout. Interleaving limits the drift this causes; it does not remove it.

## J2 (⌘T key → command bar): not comparable

Input never reached the 0.4.4 control in 2 runs. Both runs (08:43 and 09:53) stopped on 0.4.4's first ⌘T (journeys-0),
shortly after its launch: "Cmd-T: input delivery stopped: no key down reached the app's key log after four posts",
with the instance's main thread idle in `ChromeMain`, the display awake, no other Solara instance, test helper or
key poster running, and the uitest gate held by the bench. Both runs stopped on run 0, which is the 0.4.4 control
by the bench's order; 0.4.5 was never reached, so this doesn't show the stop is 0.4.4's.
J2 is left out of the verdict; ⌘T is covered by tab-actions cmdT (100.3 → 95.3 ms, overlapping).
Logs: `logs/j2.log`, `logs/j2b.log`, samples in `perf-gate/j2*/0.4.4/data/journeys-0/input-stopped-sample.txt`.
