# 0.3.1 → 0.3.2 release gate

0.3.2 is the toolbar fix alone (d8f2ead5): the same engine (574046ecf2af, Chromium 157.0.8103.50) and native API 40, so
native-bench ran the candidate's bench bundle on both sides and js-bench each app's own `main.jsbundle`. Candidate
`dist/0.3.2/export/Solara.app` (signed and notarized, built from e3c98392); control `dist/0.3.1/export/Solara.app`. Both
with `SOLARA_NATIVE_BOOKMARKS=1`, measured on 2026-11-11 on the Hill Studio under the perflab lock, ad hoc copies on
both sides, screen locked (paint and frame rows pending). The owner approved publishing on completion.

## Result

Launch, new window, idle wakeups and every JS action row overlap or improve. Rows whose ranges separated:

| Row | 0.3.1 | 0.3.2 |
|---|---:|---:|
| memory, browser process, 20 tabs | 189 MB (189–189) | 193 MB (191–196) |
| memory, browser process, after closing | 172 MB (172–172) | 178 MB (175–180) |
| memory, whole app, 20 tabs | 969 MB (968–969) | 973 MB (972–974) |
| idle CPU, 1 tab (all processes) | 0.35 % (0.34–0.35) | 0.37 % (0.37–0.37) |
| after an idle minute: command answered | 157 ms (156–157) | 132 ms (131–132) |
| startup.taskMs | 486 (459–622) | 442 (409–456) |
| open.medianMs | 22.2 (21.8–22.4) | 21.6 (21.5–21.7) |
| persist.bookmarksStringifyMs | 1.9 (1.9–1.9) | 2.9 (2.0–4.0) |
| pageLoad.listenerMs | 4.9 (4.6–4.9) | 5.2 (5.0–5.2) |

The fix brings back the full-sidebar toolbar's band, hairline and card surfaces, so a few MB more in the browser
process is the expected direction; the whole app stays about a quarter under 0.3.0. Each side ran twice (native) or
three times (JS); none of the rows was rerun.
