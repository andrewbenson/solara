# 0.2.5 → 0.3.0 release gate

0.3.0 has the same engine series as 0.2.5 (Chromium 156.0.8078.79) with a new engine build (c5a8cc166462, native API 40
against 0.2.5's older API), so native-bench ran each app with its own bench bundle: the candidate's from the tree, the
control's built from the v0.2.5 tag. js-bench runs each app's own `main.jsbundle`. The candidate is
`dist/0.3.0/export/Solara.app` (signed and notarized, built from 0a95cb48); the control is `dist/0.2.5/export/Solara.app`.
Both run with `SOLARA_NATIVE_BOOKMARKS=1`, which 0.2.5 ignores: the bench's re-signed copies are test builds, which own
bookmarks natively only with that switch, while a distribution build always does. Measured on 2026-11-10 on the Hill
Studio under the perflab lock, ad hoc copies on both sides (`BENCH_SIGN_IDENTITY=-`), with Dia running on that Mac
(about four cores busy, on both sides of every interleaved pair). The screen was locked, so every row that waits on a
paint or a frame reads pending.

## Result

Every row is the same within noise or better, except one JS sub-row, `switch12.listenerMs`, which separated in both
JS rounds (below).

- **Launch** (native-bench, launch x6): window shown 618 ms (529–639) → 619 ms (537–701); JS running 502 ms
  (490–608) → 507 ms (504–636). Overlap.
- **New window:** on screen 77 ms (62–91) → 82 ms (76–93). Overlap.
- **Memory** (guarded session round, below): browser process with 20 tabs 191 MB (188–193) → 185 MB (185–185);
  after closing back to one tab 172 MB (172–173) → 170 MB (169–170); whole app with 20 tabs 1292 MB (1286–1299) →
  1289 MB (1288–1290).
- **Idle wakeups:** every row overlaps in the guarded round. Renderers at 20 tabs separated once in the first round,
  10.4 (9.8–10.9) → 12.9 (12.5–13.2), and overlapped in the second, 10.7 (10.5–10.9) → 10.6 (10.4–10.9), and the
  guarded round, 11.0 (10.8–11.2) → 11.3 (10.3–12.3). Not reproduced.
- **Idle CPU with one tab** reads 3.64 % → 0.30 %, but the control's uBlock Origin didn't start from its selfie in
  any session, so its first idle minute includes uBlock compiling its lists. Not claimed as a win.

## JS (js-bench, two rounds of 3 alternating runs)

The first round found closing and switching tabs slower: close20.otherJsMs 271 (261–290) → 973 (966–1072),
switch12.otherJsMs 243 (238–279) → 377 (348–378). The cause was native tab sleep's keep-alive feed (on by default
since 0.2.5) reading every tracked page's native readiness, a synchronous main-thread call, on every flush before
comparing reports; fixed in 0a95cb48, and the candidate rebuilt. Second round, on the shipping build:

| Row | 0.2.5 | 0.3.0 |
|---|---:|---:|
| close20.otherJsMs | 263 (260–324) | 295 (289–309) |
| close20.taskMs | 717 (707–797) | 764 (749–768) |
| switch12.otherJsMs | 237 (219–259) | 224 (219–242) |
| switch12.taskMs | 506 (478–537) | 500 (493–511) |
| switch12.listenerMs | 6.5 (5.4–6.7) | 8.5 (6.9–9.1) |
| open20.otherJsMs | 3878 (3795–4066) | 2884 (2782–3121) |
| startup.bundleEvalMs | 66 (65–68) | 23 (22–23) |
| startup.bundleToFirstWindowMs | 121 (116–122) | 69 (69–80) |
| startup.launchToFirstWindowMs | 3453 (3415–3539) | 3614 (3499–3636) |
| startup.commits | 22 (22–24) | 27 (27–29) |
| typing30.otherJsMs | 37.3 (29.9–37.7) | 24.5 (22.6–25.1) |

`switch12.listenerMs` separated in both rounds (first round 6.5 (5.9–6.5) → 8.7 (8.2–11.1)): about 0.2 ms more of
store-listener time per tab switch, while the switch's total JS task time stays the same. `startup.commits` is a count:
about two commits come from the extension sheets' consumers moving into the always-mounted overlay (e57304f8), the
rest vary with launch order. `close20.listenerMs` separated in the second round only, 12.7 (12.2–13.3) → 15.7
(13.8–18.1), and overlapped in the first.

## The memory row that wasn't

Rounds 1 to 3 had the browser process about 32 MB larger on 0.3.0 (round 3: 153 MB → 185 MB with 20 tabs). native-bench
copied the candidate's compiled uBlock storage (1.76.0) into the 0.2.5 template (1.75.4), which rejected it and rebuilt
from the lists, leaving Chromium's shared LevelDB block cache about 40 MB fuller on one side (Codex job mem30: held
instances, memory-infra dumps, and a control given the candidate's whole Extensions folder, 196.3 → 196.6 MB). Since
3688a01d native-bench keeps each side's own storage when the bundled uBlock fingerprints differ; the guarded round
above is the memory result. The idle CPU and memory rows of rounds 1 to 3 aren't used.

## Ratchet

`ratchet.mjs run --own` with native bookmarks on: ok, after raising `small.launch.listenerCalls` from 509 to 590
(581 in both runs: the native bookmark projection publishing into the store at launch; 478b5e7c).

## Follow-ups

Source risks from the memory investigation, neither seen in these runs: hover-card memory readings are never
forgotten (keyed by tab and URL), and bookmark request receipts keep their payloads until the engine terminalizes
them. Both go to 0.3.1.
