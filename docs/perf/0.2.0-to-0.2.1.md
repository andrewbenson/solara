# 0.2.0 → 0.2.1 release gate

0.2.1 adds the icons-only rail A and rail B, per-window sidebar width, Picture in Picture over full-screen Spaces and
the fixes in its notes. Both apps are native API 36, so both ran the candidate's bench bundle. The candidate is
`dist/0.2.1/export/Solara.app` (notarized, built from 7ff8b04d); the control is `dist/0.2.0/export/Solara.app`.
Measured on 2026-11-04 on the Hill Studio, interleaved in one native-bench process (launch x6, session x2, windows),
then js-bench alternating the two apps for 3 rounds, under the perflab lock with nothing else of ours running.

**Ad hoc copies on both sides.** native-bench re-signs each copy with the app's own identity, and the Developer ID
identity isn't in the Hill Studio's keychain, so both copies were re-signed ad hoc for this gate, with the same
entitlements minus the three a provisioning profile grants (application identifier, team identifier, keychain
access groups). An ad hoc build uses the mock keychain, so neither side's launch includes the Safe Storage read. The
comparison is relative: both apps got identical treatment.

**The screen locked partway.** The screen was unlocked and held awake when the gate started, but it locked again during
the session and windows phases. The rows that wait on a paint or a frame left out the locked runs, as each row says.
New window → first paint is the one row whose remaining runs separate (147 ms, n=1, against 180–188 ms, n=2). With one
control run that is not a regression call; it is pending, with the other locked-out rows, until a run on an unlocked
screen (`owner-visual-checks.md`, 0.2.1).

## Result

Every gated row is the same within noise: no range separates except the bundle size (+5 KB of new code) and two rows
where 0.2.1 is better. No `## Faster` section.
